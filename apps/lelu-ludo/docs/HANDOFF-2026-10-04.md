## Learn the game: a tutorial in the style of Lelu Oware's lessons

- **Lessons.** `Game/Tutorial.swift` holds seven of them in three chapters, matching the Learn cards:
  - The board: Your yard, Home is the centre
  - How to move: Move by the roll, Kick
  - Special Ghana rules: Back kick, A wall, The black star 6
- **How a lesson is built.** Each is an arranged position on the real board, with Ghana Classic
  rules, scripted dice and a goal (`GameEvent`).
- **Session API (`LudoSession`):**
  - `startTutorial(at:)`, `nextLesson()`, `retryLesson()`, `endTutorial()`
  - During a lesson Black is a seat that is never asked to move; `canRoll` stops once the lesson is
    done or failed.
  - **A lesson never saves.** `endTutorial()` puts the player's own game back.
- **Game screen.** `GameView` shows a `LessonPlaque` (what to do, then why it worked) with Next/Finish
  or Try again. The back button ends the lesson.
- **Tests:**
  - `LeluLudoTests/TutorialTests` (4): every lesson can be done under the real rules; a wrong move
    asks to try again; Next walks through every lesson; the saved game survives.
  - UI test `testLearnTheGameFromTheMenu`.
- **Launch flag.** `--tutorial` opens straight onto lesson 1.

## Black screen before the splash

- **Cause.** The launch screen was a plain colour (`UILaunchScreen` → `LaunchBackground`, about
  #0F0A08), followed by a much brighter splash, so the eye sees "black, then splash". Lelu Oware
  has the same setup; it only looks seamless because its splash is dark.
- **Fix:**
  - `LaunchScreen.storyboard` shows `LaunchSplash` full screen (aspect-fill, pinned to the edges).
    `project.yml` uses `UILaunchStoryboardName: LaunchScreen`.
  - `LaunchSplash` is the splash's background: dark mahogany lit from above, no text (Apple's
    guidance for launch screens). It is generated by `make_art.py` (`launch_splash`); it no longer
    uses `art/source/splash.png`. `SplashView` draws the same image as its background and puts
    the title, the line and the board on top, so launch runs into it with no black and no jump.
    It must stay a JPEG at the **top level** of `Assets.xcassets`; a 1.4 MB PNG inside `Art/`
    showed a blank frame.
- **Verifying it — the simulator caches launch snapshots per bundle ID, even after an uninstall:**
  - A re-test on the same bundle ID can still show the old dark frame. Build with
    `PRODUCT_BUNDLE_IDENTIFIER=com.richardforjoe.leluludo.launchcheck`, or reset the simulator.
  - Builds made with `CODE_SIGNING_ALLOWED=NO` cannot draw a launch image at all. Use ad-hoc
    signing: `CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM=`.
  - On a phone, delete and reinstall, or install a new build.
  - Record with `xcrun simctl io booted recordVideo`, then pull frames with ffmpeg. With a fresh
    bundle ID the art shows from the first frame of the zoom.
- **No longer open:** `splash.png`'s duplicated tagline, its cropping on iPad and its softness on Pro
  Max screens. The launch image no longer uses `splash.png`, and the splash draws its title as text.

## TestFlight pipeline (PR #69)

- **Files:** `apps/lelu-ludo/fastlane/` (Appfile, Fastfile, Matchfile, README) and
  `.github/workflows/testflight-ludo.yml`, plus a Lelu Ludo section in `docs/PIPELINE.md`.
- **How it compares with Oware:**
  - It reuses Oware's secrets, team and match certificates repo.
  - Builds are tagged `build/ludo-<version>-<build>`, which Oware's release workflow never matches.
  - Uploads pass the app's App Store Connect ID, `6818915279` (`APP_STORE_ID` in the Fastfile).
- **One-time steps for the owner:** the bundle ID and App Store Connect record already exist (SKU
  `leluludo-ios` suggested).
  1. Run match once from `apps/lelu-ludo`:
     `BUNDLE_GEMFILE=../../Gemfile bundle exec fastlane ios setup_signing`
  2. Add an internal tester group under Lelu Ludo ▸ TestFlight.
  3. Merge, or run "TestFlight (Lelu Ludo)" by hand.
- **Not mirrored from Oware:**
  - The version comes from `MARKETING_VERSION` in `project.yml` and is raised by hand.
  - TestFlight notes still use `next_version.py`, which counts from Oware's `v` tags.
  - There is no App Store release workflow for Ludo yet (follow-up in `docs/PIPELINE.md`).

## How this session checked the UI

- **Screenshots.** A throwaway UI test (`LeluLudoUITests/ZZShots.swift`, deleted afterwards) wrote
  `XCUIScreen.main.screenshot()` to a path on the Mac. Run it with
  `-only-testing:LeluLudoUITests/ZZShots`, then `xcodegen generate` again after deleting it.

- **Art build.** It needs Pillow, numpy and scipy (`art/requirements.txt`). Use a venv outside the
  repo, because `.venv` is not gitignored here.
